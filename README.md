# OpenRKN Manager

OpenFlux exit node в режиме L4 для **OpenWrt 25 / x86_64**, с веб-оболочкой OpenRKN. Бэкенд написан на POSIX sh для BusyBox ash; процессы запускает procd, команды интерфейса проходят через авторизованный rpcd / ubus.

## Установка

Подключитесь к роутеру по SSH как root. Роутеру нужен доступ в интернет и доступные пакеты для его версии ядра.

```sh
wget -O /tmp/openrkn-install.sh https://raw.githubusercontent.com/DJEBAN228/OpenRKN-Manager/main/deploy.sh
sh /tmp/openrkn-install.sh
```

Установщик поддерживает apk и opkg, устанавливает зависимости и официальный OpenFlux **v0.3.0** с проверкой SHA256. **Zapret устанавливается и настраивается отдельно.** ARM, Debian и другие платформы этим установщиком не поддерживаются.

Откройте **http://192.168.1.1:7788/openrkn/** (замените IP на адрес LAN роутера). Вход — существующие логин и пароль OpenWrt, обычно root. Установщик не меняет пароль и не отключает авторизацию ubus.

Если после установки прежней версии `/openrkn/` возвращает **403 Forbidden**, исправьте права публичной оболочки и индекс uhttpd через SSH:

```sh
find /www/openrkn -type d -exec chmod 755 '{}' \;
find /www/openrkn -type f -exec chmod 644 '{}' \;
chmod 755 /usr/lib/openrkn /usr/libexec/openrkn
chmod 644 /usr/lib/openrkn/*.sh
uci -q delete uhttpd.openrkn.index_page
uci add_list uhttpd.openrkn.index_page='index.html'
uci commit uhttpd
/etc/init.d/uhttpd restart
/etc/init.d/openrkn restart
```

Открывайте адрес с портом **7788**. Если 403 остаётся, проверьте `ls -ld /www /www/openrkn /www/openrkn/index.html` и `uci show uhttpd.openrkn`.

## Подключение телефона

1. Откройте вкладку OpenFlux. По умолчанию выбран **Mail.ru Docs**. Укажите HTTPS-ссылку документа, доступного для редактирования по ссылке, и сохраните настройки.
2. Нажмите **Запустить**, дождитесь запуска и нажмите **Получить QR-профиль**. Причина ошибки доступна в журнале. До настройки документа установщик и procd не запускают OpenFlux.
3. Отсканируйте QR в совместимом клиенте OpenFlux. Для галереи скачайте **QR (.png)**: файл содержит только код с белой рамкой и целым числом пикселей на модуль. Используйте его вместо снимка интерфейса. QR также можно увеличить; на том же телефоне скопируйте ссылку и импортируйте её в приложении. Для CLI можно скачать ZIP с `mobile.conf`, `secret.key` и `share.link`, распаковать рядом и запустить клиент с этим конфигом.

Если ссылка слишком длинная для стандарта QR, копирование и ZIP остаются доступны. Независимый декодер в тестах проверяет короткие и длинные сжатые ссылки. Камера/галерея конкретного Android-клиента на настоящем телефоне здесь не проверялись.

Профиль содержит ключ доступа к exit node. Он общий для этой конфигурации, сохраняется при повторном экспорте и не является одноразовым. Смена транспорта требует нового QR. Изменение конфигурации перезапускает сервис и разрывает активные соединения.

## Mail.ru Документы и другие транспорты

Во вкладке **OpenFlux → Настройки подключения** выберите **Mail.ru Docs**, укажите HTTPS-ссылку общего доступа на документ Mail.ru, доступный для редактирования без авторизации, и нажмите **Сохранить настройки**. Backend сохраняет конфигурацию и UCI, перезапускает работающий сервис. Затем получите новый профиль. Автоматическое создание документа и вход в аккаунт Mail.ru не реализованы.

В версии OpenRKN **0.3.1 / API 4** доступны метод (Mail.ru, Яндекс, Direct), шифрование, свой ключ и кодек. Пустое поле ключа сохраняет существующий секрет; новый ключ должен содержать 16–128 символов ASCII: буквы, цифры, `_`, `-`. Ключ хранится в отдельном файле с правами 640 и не возвращается через `get_config`, не сохраняется в UCI или журнале.

Для документных транспортов можно выбрать **совместимый режим**: одиночный `[Interface] Transport/URL` с ключом позволяет OpenFlux v0.3.0 принимать сеансовых и старых клиентов. **Строгий режим** добавляет `--negotiate`. Шифрованный профиль использует **batched (zstd)**. **Legacy (LZ4)** доступен при отключённом шифровании: профиль тогда содержит одиночный транспорт без секций `[Transport]`, которым upstream требует ключ. Ограничение шифрованного legacy введено для корректного импорта QR: upstream экспортирует для зашифрованного выхода `negotiate=true`, а строгий запуск с legacy отклоняется. Direct требует ключ, batched, публичный адрес и доступный TCP-порт 8443; открытие порта и проброс через NAT выполняются отдельно. L4 остаётся режимом выхода.

При отключённом шифровании туннель не защищён ключом. Сохранённый ключ остаётся на роутере для последующего включения. После смены метода, ключа, кодека или протокола **получите новый QR и заново импортируйте профиль на телефоне**.

Если LuCI открывается, а интернет на телефоне отсутствует, нажмите **Проверить интернет роутера**. RPC `check_connectivity` выполняет три ограниченные по времени проверки: ping `1.1.1.1`, DNS `example.com` и HTTPS `https://example.com/`; суммарно до 9 секунд, только по нажатию. Это проверка выхода роутера, а не туннеля телефона. ICMP может блокироваться при рабочем интернете. При успешном HTTPS проверьте доступность редактируемого документа, импорт нового профиля, совпадение протоколов и журнал OpenFlux; при ошибках DNS/HTTPS сначала проверьте WAN и DNS в LuCI. Совместимый режим помогает при различиях версий, но без журналов роутера причина конкретного сбоя не установлена.

Аналогично доступен Yandex.Docs с HTTPS-ссылкой документа. Direct требует адреса, доступного телефону, и TCP-порта 8443. Для подключения из интернета отдельно настройте firewall / NAT; установщик не открывает этот порт в WAN автоматически.

При обновлении поддерживаемые настройки Mail.ru, Yandex и Direct сохраняются. Конфигурация неподдерживаемого транспорта сохраняется как `/etc/openrkn/exit.conf.previous`, после чего выбирается шаблон Mail.ru без URL. Ключ шифрования сохраняется; нужно указать документ и получить новый профиль.

Реальная доступность и скорость зависят от провайдера и выбранного транспорта. ONLINE означает живые процессы, а успешное подключение клиента нужно проверить отдельно.

## Внешний Zapret и firewall4

Рекомендуем [StressOzz/Zapret-Manager](https://github.com/StressOzz/Zapret-Manager). Установите через него **Zapret**, настройте стратегию и списки доменов для вашего провайдера, затем запустите службу. Поддерживаемая интеграция — пакет [remittor/zapret-openwrt](https://github.com/remittor/zapret-openwrt), который использует этот менеджер. Другие реализации и Zapret2 требуют отдельной проверки.

OpenFlux в режиме L4 создаёт обычные исходящие TCP/UDP-сокеты на роутере. Они проходят `output → postrouting`; стандартные исходящие правила указанного Zapret обрабатывают подходящий трафик, в том числе локальный. Порты, интерфейсы WAN, фильтры меток, списки и исключения определяет конфигурация Zapret. Правило только в `forward` локальные сокеты OpenFlux не охватывает. Добавлять отдельную NFQUEUE перед стандартными правилами Zapret не нужно.

OpenRKN не устанавливает и не запускает второй nfqws, не меняет `/etc/config/zapret` и не перезапускает внешний Zapret. Собственная цепочка `openrkn_output` в fw4 содержит только счётчик трафика UID 453. Предыдущая очередь OpenRKN удаляется при обновлении правил fw4.

В оболочке есть плашка с рекомендацией менеджера и состояниями: не установлен, остановлен, не настроен, не найдены правила исходящего трафика, требуется проверить фильтры, конфигурация обнаружена. Обнаружение процесса/правил не доказывает обработку конкретного сайта: проверьте счётчики Zapret, охват доменов и результат на телефоне. При отсутствии Zapret OpenFlux можно запустить, но DPI-обработка не подтверждается.

procd перезапускает завершившийся OpenFlux. Дополнительный watchdog раз в 60 секунд проверяет его PID и исполняемый файл. Журнал `/tmp/openrkn.log` ограничивается и ротируется; share-ссылки и QR исключены из него. Журналы внешнего Zapret смотрите в его менеджере.

## Медленная загрузка и LuCI с телефона

Для LuCI подключите телефон к LAN/Wi-Fi роутера, отключите туннель OpenFlux для этой проверки и откройте `http://192.168.1.1/` (ваш IP LAN). В обзоре OpenRKN есть кнопка «Открыть LuCI» для стандартного HTTP-порта. LuCI должен быть установлен на роутере. Если адрес/порт LuCI изменён, используйте свой.

Для медленного YouTube / Instagram сначала проверьте плашку Zapret и его настройки. Наличие туннеля Mail.ru само по себе не снимает ограничения у интернет-провайдера выходного роутера. Обработка DPI не меняет публичный IP выхода. Настройка nfqws также не гарантирует рост пропускной способности самого транспорта.

Чтобы отличить проблемы транспорта от DPI, сравните работу телефона без туннеля в локальной сети и через OpenFlux; при наличии доступного адреса exit node сравните также Direct. Direct в LAN не требует открытия WAN-порта. Для диагностики OpenRKN:

```sh
ubus call openrkn status '{}'
ubus call openrkn get_logs '{"lines":100,"service":"openflux"}'
```

## Управление и файлы

```sh
/etc/init.d/openrkn start
/etc/init.d/openrkn restart
/etc/init.d/openrkn stop
ubus call openrkn status '{}'
ubus call openrkn get_logs '{"lines":100}'
ubus call openrkn gen_mobile_profile '{}'
```

- `/etc/config/openrkn` — автозапуск, transport и URL.
- `/etc/openrkn/exit.conf` — конфигурация OpenFlux; интерфейс обновляет её при сохранении настроек.
- `/etc/openrkn/secret.key` — постоянный ключ (root:openrkn, 0640).
- `/usr/libexec/rpcd/openrkn` — методы status, capabilities, dpi_state, get_config, configure, start_service, restart_service, stop_service, gen_mobile_profile, get_logs.
- `/usr/share/rpcd/acl.d/openrkn.json` — отдельные права чтения и администрирования. Экспорт секретов доступен администратору.
- `/usr/share/nftables.d/table-post/90-openrkn.nft` — включение в fw4 без отдельных команд добавления правил.

Статистика берётся из `/proc`, `/sys` и netifd. Не реализованные разделы исходной оболочки (дополнительные proxy cores, Telegram, routing) обозначены прямо и не показывают выдуманные данные. Самостоятельный HTML через file:// не имеет доступа к ubus: открывайте оболочку с роутера.

## Разработка и проверка

```sh
node tests/host.cjs
node tests/web.cjs
npm ci --ignore-scripts
node tests/qr.cjs
node tests/build-bundle.cjs
```

Host-тестам нужен Node.js и dash (Windows: Git for Windows, либо `DASH_PATH`). Проверяются POSIX-синтаксис, RPC/ACL, ограничение журналов, экспорт и очистка профилей, настройки Mail.ru, состояния внешнего Zapret, отсутствие второй NFQUEUE, авторизация JSON-RPC, ZIP и декодирование QR. npm-зависимость jsQR используется только в тестах: на роутере Node.js не нужен. GitHub Actions запускает проверки на Linux. `node tests/preview-server.cjs` открывает тестовый стенд на localhost:8787 с явно фиктивными данными; это не router backend.

`openrkn-deploy.tar.gz` содержит `deploy.sh` и дерево `files/`, без бинарников и ключей. Для локальной установки распакуйте архив и выполните `sh deploy.sh`.

Makefile предназначен для интеграции дерева файлов в OpenWrt SDK; бинарники и первичная генерация ключа выполняются установщиком `deploy.sh`. Для готовой установки используйте установщик.

Проверены host-тесты и работа оболочки с тестовым ubus. Сквозной туннель, загрузка пакетов и firewall на реальном OpenWrt-роутере здесь не проверены.
